# fish_log CSV 형식 (77열)

`data_logger_node`가 100 Hz로 쓰는 블랙박스 로그. 파일 위치 `~/ros2_ws/log_csv/`,
파일명 `fish_log_YYYYMMDD_HHMMSS.csv`. (`log_csv/`는 gitignore 대상이라 이 문서만 `docs/`에 둔다.)
> **열 번호가 아니라 헤더 이름으로 읽을 것.** 새 열은 항상 뒤에 붙지만 열이 늘어나는 중이고,
> 1014 임시 빌드 파일은 64열(`Scenario`)까지만 현재 형식과 같다. `awk` 로 번호를 쓸 때는
> `head -1` 로 그 파일의 열 수를 먼저 확인한다.

2026-10-31부터 77열 (74~77 = pitch 각속도 종속 제어). 10-15~10-30 은 73열 (65~73 = 회차·잠긴 설정·PID 상태·배터리). 10-14 는 64열 (64 = `Scenario`). 10-07~13 은 63열 (63 = `Epoch(s)` 절대 시각). 09-16~10-06 은 62열 (48~55 대기창 영점, 56~62 MPU9250; 08-25~09-15 는 47열, 08-21~24 는 39열, 08-18~20 은 36열, 그 전은 23열 — 앞쪽 열의 의미는 모두 동일).

## 저장 방식 — 반드시 알고 분석할 것

- **스냅샷 모델**: 콜백은 최신값을 저장만 하고, 10 ms 타이머가 그 순간의 스냅샷을
  한 줄로 쓴다. 즉 한 행은 "같은 순간"이 아니라 **"그 시점까지 도착한 각 토픽의
  최신값"**이다. 열마다 나이가 다르다 (아래 갱신율 참조).
- **시계는 Pi 하나뿐**: nRF는 타임스탬프를 보내지 않는다 (46B 패킷에 시각 필드 없음).
  `Time(s)`는 로거 기동 기준 Pi 경과 초. UART 전송 지연 ≈ 4 ms(상수), 행 내
  열 간 어긋남 최대 ±1행(10 ms).
- **로테이션**: 파일당 200 MB(약 2.0시간)에서 새 파일로 넘어간다. `Time(s)`는
  파일 경계를 넘어 이어지므로 그대로 이어붙여 분석하면 된다.
- **마지막 행은 잘려 있을 수 있다** (정지 순간 쓰다 만 줄). 열 수가 안 맞는 행은 버릴 것.
- **초기값 구간**: 기동 즉시 기록을 시작하므로, 센서가 붙기 전 구간은 초기값
  (0, 서보 1500, BLDC 1000)이 그대로 찍힌다. 실수신 시작 시각은 저널 INFO에 남는다.

## 대기창 영점 열 (48–55) — 2026-09-16

공기 중 영점은 입수 뒤 무효다(젖으면 채널마다 영점이 흘러 정지 상태에서 `Speed` 가 +0.3~0.4 m/s
남는다 — 0913·0914·0915 수조 로그). 그래서 `hydro_estimator_node` 가
**AUTO 진입 대기(`State`=1, `start_delay_sec`) 동안** 로봇이 조용한 구간의 `Q_raw − P_hydro` 중앙값을 그 주행의 영점으로 잡고,
`State` 가 2 로 넘어가는 순간 확정한다. 실행마다 새로 잡는다.

- **영점 결정 순서**: ① `Still`=1 이 연속 2 초 이상인 구간 중 **가장 늦은** 것 → `Zero_src`=1
  ② 없으면 대기 마지막 2 초의 중앙값 → 2 ③ 유효 샘플 5 개 미만 → `Q_zero`=0, `Zero_src`=0.
- **한 행의 `Q_zero` 는 언제나 그 행이 속한 주행의 것이다.** WAIT 에 들어가면 이전 값을 지우므로
  (`nan`), WAIT 행에서 `Q_zero` 가 보이면 그건 압력 주기(~19 Hz) 지연으로 남은 직전 주행의 마지막 샘플이다.
  주행이 끝난 뒤(`State`=0, AUTO 유지) 에도 `Q_dyn_wz`/`Speed_wz` 는 계속 계산된다 — 꼬리 OFF 후
  정지 검사에 쓴다.
- **기존 41·42열은 손대지 않았다.** `Speed`/`Q_dyn` 은 종전 그대로(공기 Δb 영점 + LPF + 데드밴드),
  새 열은 필터 없는 샘플값이다 — 사후 분석이 같은 식을 오프라인으로 돌려 대조하기 위해서다.
  1 초 평균을 낼 때는 `Q_dyn_wz` 를 평균한 뒤 제곱근을 취할 것(속도를 평균하면 Jensen 편향).
- 정지 판정에 쓰는 수심 변화율은 27–29열 `GX..GZ` 와 37–39열 `P1_raw`/`P2_raw` 평균의 1 초 선형회귀
  기울기로 오프라인 재현된다 (바이어스 안 뺀 원시 자이로 크기, 대기압 영점 무관).
- 문턱은 `wet_zero_*` 파라미터 (operation.md 7.3). 폴백(`Zero_src`=2)이 잦으면 대기가 짧은 것이다 —
  버튼 직후 4~5 초는 가라앉는 중이라 `start_delay_sec` 10 이 권장값.

주행별 요약 한 줄:

```bash
awk -F, 'NR>1 && NF==62 && $55==2 && p!=2 {printf "t=%.2f  Q_zero=%s src=%s 구간 %s~%s\n",$1,$48,$49,$50,$51} {p=$55}' fish_log_*.csv
```

## 2번째 IMU 열 (56–62) — 2026-09-16

`i2c_driver_node` 가 지자기(AK8963)를 꺼내려고 바이패스만 켜 두던 MPU9250 의 **자체 6축을 감시용으로 읽는다.**
EKF 도 제어도 이 값을 쓰지 않는다 — CSV 에만 남는다. 목적은 하나다: nRF IMU 자이로(27–29열)의 바이어스가
세션마다 50배씩 다르고 온도로도 흐르는데, 자이로가 하나뿐이면 "요가 흘렀다"가 자이로 탓인지 필터 탓인지
가릴 수 없다. 같은 로봇에 붙은 두 자이로는 **진짜 회전은 똑같이 읽고 바이어스만 독립**이므로,
둘의 차이가 벌어지는 순간이 곧 바이어스가 튄 순간이다.

- **축은 맞춰져 있다.** 두 칩은 다른 방향으로 붙어 있지만, `i2c_driver_node` 가 MPU 값을 **nRF IMU 칩 축으로
  돌려서** 보낸다 (`nRF_x = −MPU_y, nRF_y = +MPU_z, nRF_z = −MPU_x`, 2026-09-16 정지 중력 벡터 짝짓기로 실측,
  det +1, 잔차 0.96°). 그래서 `MPU_GX − GX` 처럼 열끼리 바로 뺀 값이 곧 두 자이로의 **바이어스 차**다.
  FLU 몸체 축으로 가려면 두 쪽 다 같은 `(−z, −x, +y)` 변환을 쓴다.
  ※ 자이로 쪽 순열은 가속도에서 구한 것을 그대로 쓴다(두 칩 다 가속도·자이로가 축을 공유). 회전 시험으로
  따로 확인한 적은 아직 없으니, 첫 로그에서 로봇을 굴린 구간의 `GX`↔`MPU_GX` 가 같이 움직이는지 한 번 볼 것.
  nRF IMU 를 다시 장착하면 순열도 다시 재야 한다.
- **정지 구간에서 각 열의 평균 = 그 자이로의 바이어스.** 벤치 실측(2026-09-16, 정지, nRF 축 기준): nRF 자이로
  (+0.15, −3.16, −0.50), MPU 자이로 (+2.51, −0.33, −1.07) 도/초, MPU 온도 38 °C — 서로 무관한 값이라는 것이
  독립성의 증거다. 한 세션 안에서 각각이 얼마나 움직이는지가 곧 바이어스 안정성이다.
- 62열 온도와 59–61열을 같이 그리면 바이어스-온도 기울기가 나온다 (알려진 갭: 센서 근처 열 드리프트).
- 갱신 100 Hz (칩 내부 200 Hz 에서 틱마다 최신값) 라 24–29열처럼 매 행 새 값이다. 읽기 실패는 `nan`.

## EKF_Flags 비트

| 비트 | 의미 |
|---|---|
| 0x01 | 초기화 완료 |
| 0x02 | 가속도 갱신 적용됨 |
| 0x04 | 지자기 yaw 갱신 적용됨 (9축 정상) |
| 0x08 | 가속도 기각 (교란 감지) |
| 0x10 | 지자기 기각 (복각/크기 게이트) |
| 0x20 | **지자기 두절 — 6축 폴백 중** |

정상 9축 = 7 (0x01\|0x02\|0x04). 기동 직후 0 → 3 → 7 전이는 정상 (초기화 → 지자기 기준 확보).

### 속도가 `nan`일 때 — 47열만 보면 원인을 짚을 수 있다

`Speed`는 아래 조건이 **전부** 충족돼야 나온다. 하나라도 빠지면 `nan`이고, 무엇이 빠졌는지가
플래그에 그대로 남는다:

| 켜져 있으면 | 원인 | 무엇을 하나 |
|---|---|---|
| `0x040` | 앞 포트 사망 | 분해 |
| `0x080` 또는 `0x100` | 정압 포트 사망 | 분해. **한쪽만 죽어도 속도는 안 낸다** (롤 상쇄가 깨져 롤 30°에서 2.1 mbar 누락) |
| `0x020` | 자세 없음 | IMU/nRF, EKF 확인 |
| `0x800` | 압력 스트림 정지 | I2C 버스 |
| **`0x008`이 꺼짐** | **물속 q 영점 미확보** | 물에 넣고 잔잔해진 뒤 `/hydro/zero_q` |

`0x008`만 꺼져 있고 나머지가 멀쩡하면 **하드웨어는 정상이고 영점만 안 잡은 것**이다.

`Q_raw`(43열)는 **위 어느 경우에도 계속 기록**되므로, 원인을 고친 뒤 그 구간을
오프라인에서 다시 계산할 수 있다.

한 줄로 훑어보기:

```bash
awk -F, 'NR>1 && $41=="nan" {c[$47]++} END {for(f in c) printf "flags %5d (0x%03X) : %d행\n", f, f, c[f]}' fish_log_*.csv
```

## 모드와 시나리오 — 무엇이 돌았나 (4·55·64열)

세 열을 같이 봐야 한다. 10-03 로그에서 주행 10회가 분명한데 어느 시나리오였는지 CSV 로
가릴 수 없어 저널을 뒤져야 했고, 그래서 2026-10-14 에 `Scenario` 열을 넣었다.

| 열 | 뜻 |
|---|---|
| 4 `AutoMode` | 0 = **MANUAL**(조종기 조종), 1 = AUTO |
| 55 `State` | AUTO 진행: 0 IDLE · 1 WAIT(진입 대기) · 2 RUN(주행) |
| 64 `Scenario` | 걸린 시나리오 ID (위 표) |

- **MANUAL 구간**은 `AutoMode`=0 이고, 그때 `Scenario` 는 "지금 걸려 있는(= 다음에 돌)"
  시나리오다. 그 구간에 실제로 돌아간 것은 아니다.
- **실제 주행 구간은 `State`=2** 다. 대기(1)와 주행(2)을 합쳐 보려면 `State>0`.
- 번호는 `auto_scenario_node` 의 `SCEN_*` enum 과 짝이다. **재배정하면 지난 로그의 해석이
  깨진다** — 새 시나리오는 뒤 번호로 붙인다. 바꿀 때는 그 enum, `data_logger_node` 의
  해독, 이 표 **세 곳을 같이** 고쳐야 한다.
- 토픽은 `/auto/state` 하나이고 `100*시나리오ID + 상태` 로 실려 온다. 상태만 쓰는 쪽
  (`hydro_estimator_node`)은 `% 100` 을 한다.

```bash
# 주행 구간만, 시나리오 이름과 함께
awk -F, 'NR>1 && $55==2 {n[$64]++} END {split("모름 straight dive climb porpoise attitude bank_left bank_right static",m," ");
  for (k in n) printf "  %-11s %6d행 (%.1f초)\n", m[k+1], n[k], n[k]/100}' fish_log_*.csv

# 주행 시작 시각마다 어느 시나리오였나
awk -F, 'NR>1 && $55==2 && p!=2 {printf "t=%.2f  Scenario=%s\n",$1,$64} {p=$55}' fish_log_*.csv
```

# 회차별 요약 — 주행 구간만
awk -F, 'NR>1 && $55==2 && $65!=p {p=$65;

## pitch 각속도 종속 제어 (74–77열, 2026-10-31)

| 열 | 이름 | 단위 | 뜻 |
|---|---|---|---|
| 74 | `Kp_rate` | 초 | 그 순간의 `kp_pitch_rate`. **0 = 각속도 제어 꺼짐** |
| 75 | `Rate_used` | 0/1 | 그 틱에 각속도 항이 실제로 출력에 들어갔나 |
| 76 | `Rate_meas` | 도/초 | LPF(τ=0.05 s) 통과 pitch 각속도 |
| 77 | `Rate_err` | 도/초 | 목표 각속도 − 측정 각속도 |

`pid_control_node` 의 제어식은

```
목표각속도 = clamp(kp_pitch_angle × 각도오차, ±pitch_rate_max)
Rate_err   = 목표각속도 − Rate_meas
u_pitch    = kp_pitch × (각도오차 + Kp_rate × Rate_err)
```

- **`Kp_rate`=0 이면 74~77열은 진단값일 뿐 출력과 무관하다.** `Rate_meas`/`Rate_err` 는 그래도
  계산되어 기록되므로, **켜기 전에 "켰다면 얼마나 개입했을지"를 로그로 미리 볼 수 있다.**
  `Rate_used` 는 이때 0 이다.
- **`Rate_used`=0 인데 `Kp_rate`>0 이면 각속도가 낡아서(50 ms 초과) 그 틱만 각도 제어로
  복귀한 것**이다. 주행 구간에서 이 비율이 높으면 `/filtered/angular_rate` 전달에 문제가 있다는
  뜻이므로 게인을 만지기 전에 그것부터 봐야 한다.
- **`Rate_meas` 는 목표가 0° 일 때도 0 이 아니다.** `straight` 실측 중앙값이 4.8 도/초인데,
  자세가 틀어진 게 아니라 **꼬리 박자에 몸통이 떠는 것**이다 (`static` 은 0.5). 이 떨림을 자세
  오차로 읽지 말 것.
- **69~72열과 같은 이유로 페일세이프·`static` 구간에는 직전 값이 남는다** (`/pid/debug` 미발행).
- **구 `pid_control_node`(4칸 발행)와 섞이면 74~77열만 멈춘다.** 로거는 크기 4 와 8 을 따로
  검사하므로 69~72열은 계속 갱신된다 — 두 열 묶음의 갱신 시각이 다를 수 있다.

```bash
# 각속도 제어를 켠 주행 구간만
#   ※ $74>0 만 쓰면 awk 가 "nan" 을 문자열로 비교해 걸러지지 않는다. nan 검사를 같이 쓸 것.
awk -F, 'NR>1 && $55==2 && $74!="nan" && $74+0>0 {print $65, $74}' fish_log_*.csv | sort -u

# 켜기 전 사전 조사 — "켰다면" 개입량 분포 (주행 구간)
awk -F, 'NR>1 && $55==2 && $77!="nan" {s+=$77*$77; n++}
         END {printf "Rate_err RMS = %.2f 도/초 (n=%d)\n", sqrt(s/n), n}' fish_log_*.csv

# 각속도 유실률 — 켠 뒤에 확인할 것
awk -F, 'NR>1 && $55==2 && $74!="nan" && $74+0>0 {n++; if($75==0) m++}
         END {if(n) printf "복귀 %d/%d (%.1f%%)\n", m, n, 100*m/n}' fish_log_*.csv
```

## 절대 시각으로 맞추기 (63열, 2026-10-07)

`Time(s)`(1열)는 **로거 기동 기준 경과 초**라 그 자체로는 다른 장비 기록과 맞출 수 없다.
`Epoch(s)`(63열)가 그 역할을 한다 — 양쪽을 유닉스 시각으로 바꿔 빼면 끝이고, 시간대나 서머타임을
신경 쓸 필요가 없다.

```bash
# 사람이 읽기
date -d @1791356371.499                    # 2026-10-07 15:59:31
# 로거 기동 시각 (파일 어디서든 같은 값)
awk -F, 'NR==2 {printf "%.3f\n", $63-$1}' fish_log_*.csv
# 예인 장치 파일 velocity_0.2_20261005_144706.txt 가 시작된 순간의 행
T=$(date -d "2026-10-05 14:47:06" +%s)
awk -F, -v t=$T '$63>=t && $63<t+1' fish_log_20261005_143806.csv
```

- **구간 길이·주기는 `Time(s)` 로 계산한다.** `Epoch` 는 벽시계라 NTP 가 시각을 당기면 뒤로 뛸
  수 있다. 두 열을 다 남기는 이유가 이것이다 — `Time(s)` 는 단조 증가, `Epoch` 는 다른 기록과의 접점.
- `Epoch − Time(s)` 는 파일 회전을 넘어도 **일정하다**(실측 흔들림 0.0 ms). 그래서 회전된 파일들을
  그대로 이어붙여도 절대 시각이 유지된다 — 파일명으로 역산하면 두 번째 파일부터 어긋난다(파일명은
  그 파일이 만들어진 시각이고 `Time(s)` 는 이어지므로).
- 10-06 이전 파일에는 이 열이 없다. 그때는 **첫 파일의 파일명**(`fish_log_YYYYMMDD_HHMMSS`)이
  `Time(s)=0` 의 시각이므로 초 단위로 역산할 수 있다.

## 분석 시 함정 5가지

1. **축 프레임이 열마다 다르다**: AX..GZ·MX..MZ는 칩 축, BiasX..Z와 Roll/Pitch/Yaw는
   FLU 몸체 축. 원시 자이로에서 바이어스를 직접 빼면 틀린다 — 칩→몸체 변환
   `(bx, by, bz) = (−gz, −gx, +gy)` 를 거친 뒤 뺄 것
   (실측 대조: BiasZ −3.06 ↔ 원시 GY −3.0).
2. **저주기 열은 계단(sample-and-hold)이다**: Bias·Flags는 ~10행, 압력은 ~5행씩 같은 값이
   반복된다(2026-09-19 이전 파일은 ~9행). **온도(20–22열)는 그보다 훨씬 긴 ~55행** — 드라이버가
   10사이클에 한 번만 변환하기 때문이다. 미분하거나 스펙트럼을 보면 안 된다.
3. **같은 행의 자세와 원시 6축은 같은 샘플이 아니다**: 최대 ±1행(10 ms) 어긋날 수
   있다. 구조적인 것이므로 맞추려 들지 말 것.
4. **압력은 두 벌이고 서로 다른 것을 뜻한다**: 17–19열(`_cal`)은 EKF가 잡은 대기압
   영점이 이미 빠진 게이지압이고, 37–39열(`_raw`)은 영점 전 절대압이다. 수심·피토
   차압을 다른 상수로 다시 계산하려면 **반드시 `_raw` 쪽을 쓴다** — `_cal`은 영점이
   섞여 있어 역산이 안 된다. 반대로 그 차이(`raw − cal`)가 곧 그 세션의 영점 값이다.
   (`_raw`는 이름과 달리 드라이버의 IIR을 거친 값이지만, 2026-08-19부터 그 필터가
   임시로 우회돼 있어 현재 파일들은 진짜 무필터다.)

6. **56–61열 `MPU_*`는 24–29열과 같은 축(nRF IMU 칩 축)이지만 같은 센서가 아니다**: 값의 차이는
   바이어스·배율 차이지 회전이 아니다. 정지에서 두 자이로가 서로 다른 값을 읽는 것이 정상이다 — 그
   차이가 시간에 따라 **변하는지**를 봐야 한다 (위 "2번째 IMU 열").

5. **45열 `Hydro_Pitch`와 6열 `Pitch`는 같은 양인데 값이 다르다**: 6열은 그 순간의
   100 Hz 스냅샷이고, 45열은 **압력이 대표하는 72 ms 과거**를 보간한 값이다. 다르다고
   버그가 아니다 — 오히려 **두 열의 상호상관 지연이 파이프라인 지연의 실측치**다.
   정지 상태에서는 둘의 차이가 잡음 수준(0.005°)이라 지연을 잴 수 없다. ω ≳ 20 °/s로
   흔들어야 의미 있는 값이 나온다.
