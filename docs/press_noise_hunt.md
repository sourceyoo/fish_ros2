# 압력 센서 잡음 원인 규명 지시서 (2026-10-30)

## 0. 먼저 읽을 것

`CLAUDE.md` 의 §7 하드웨어 특이점 (압력 부분 전체) 과 `docs/imu_detailed.md` §10.3, §10.4, §13.
**§13 은 이 지시서의 직전 작업이다** — 거기서 내린 결론을 **검증**하는 것이 이 작업의 핵심이고,
거기 적힌 숫자를 다시 재는 것은 일이 아니다.

---

## 1. 무엇을 찾는가

압력 σ 가 데이터시트의 8~15배인 것은 **두 개의 서로 다른 현상**으로 분해됐다.

| 층 | 정체 | 상태 |
|---|---|---|
| 표본 단위 (σ 0.13~0.24 mbar) | 칩 내부 오버샘플링 잡음 | **확정** (무상관·√3·OSR 2.01배) |
| 1초 평균 (√N 보다 2.2~3.7배 나쁨) | 워밍업 온도 드리프트 | **가설** — 사후 재분석으로만 뒷받침 |

**이 작업의 목표는 아래 셋이다.**

1. **1번 가설을 사전 예측으로 검증한다.** §13 은 과거 자료 2건을 *사후에* 분해해 얻은
   결론이다. 사후 설명은 거의 항상 맞아 보인다 — 예측이 맞아야 한다.
2. **채널별 온도 민감도 계수를 실측한다.** §13 이 남긴 유일한 실무적 위험은 차압 자세다.
   세 채널의 온도 변화가 +0.6/+2.9/+3.0 °C 로 5배 달랐으므로 상쇄가 불완전하다. 계수를
   모르면 "얼마나 불완전한가" 를 답할 수 없다.
3. **표본 단위 잡음에 외부 기여가 없음을 재확인한다.** 확정된 결론이지만 센서가 3개 모두
   교체된(2026-09-08) 뒤의 개체이고, 당시 측정(2026-08-20)은 **교체 전 개체**다.
   §13 이 쓴 10-20/10-28 자료는 교체 후이므로 이미 간접 확인은 됐다 — 새로 재지 말고
   **기존 자료로 대조만** 하라.

## 2. 측정 방법 — 여기서 틀리기 쉽다

### 함정 1 — 데이터시트와 비교하지 마라

판정 기준은 **이 하드웨어의 실측 기준선**이다. `press_char.py` 가 `MEASURED_SIGMA_MBAR = 0.13`
으로 이미 그렇게 짜여 있다. 데이터시트 0.016 과 비교하면 "8~15배 나쁨" 이라는 이미 아는
결론만 다시 나온다.

### 함정 2 — 워밍업 상태를 기록하지 않으면 그 측정은 비교 불가다

§13 의 핵심이 이것이다. 10-20 과 10-28 이 정반대로 보인 유일한 이유다.
**매 기록의 온도 시작값·끝값·변화폭을 반드시 남긴다.** 다른 기록과 비교할 때는
**온도 변화폭을 먼저 맞춰라.** 다르면 1초 SD 는 비교하면 안 된다.

### 함정 3 — IIR 필터가 살아 있으면 잡음이 4.4배 작게 나온다

`press_char.py` 머리말의 경고다. 현재 `/sensor/pressure_raw` 는 **영구 생값**이고
(2026-08-26 결정, `CLAUDE.md` §7) 필터는 우회돼 있다. 측정 전에 그 상태임을 확인하라.
확인 방법: 표본 σ 가 0.1 mbar 대로 나오면 생값이다. 0.03 대로 나오면 필터가 살아 있다.

### 함정 4 — 서비스를 멈추지 마라, 그리고 수동 실행하지 마라

압력은 `i2c_driver_node` 가 I2C 버스를 잡고 읽는다. 서비스가 도는 중에 같은 노드를
손으로 띄우면 **버스를 두 프로세스가 다툰다.** `press_char.py` 는 토픽 구독자일 뿐이므로
**서비스를 켠 채로** 돌리는 것이 정상 사용법이다.

### 함정 5 — sudo 가 필요한 일은 직접 하지 말고 운용자에게 요청하라

서비스 재시작은 sudo 다. 그리고 이 작업에는 **재시작이 반드시 필요한 단계가 있다**
(찬 상태 기록). 운용자에게 요청하고, 기다리는 동안 다른 단계를 진행하라.

### 함정 6 — 자기 프로세스를 죽이지 마라

`pkill -f` / `pgrep -f` 는 자기 셸 명령문까지 매칭해 죽인다(이 세션에서 3회 발생, exit 144).
그리고 `pgrep -f` 로 센 노드 수는 **자기 자신을 포함해 과대 계수된다**(10-30 에 8개를
12개로 오독). 노드 수는 `ls -l /proc/*/exe | grep -c 'fish_robot_pkg/lib'` 로 세고,
종료는 **PID 를 명시**해서 하라.

### 함정 7 — 측정이 끝나면 CSV 를 정리하라

`press_char.py` 는 `log_csv/presschar_*.csv` 에 쓴다. 10분이면 1.5 MB 로 작지만,
**로거(`fish_log_*.csv`)는 100 Hz 73열이라 시간당 ~84 MB** 다. 측정을 위해 서비스를
길게 켜 두면 그쪽이 쌓인다. 끝나고 어느 파일이 측정용인지 밝혀 운용자에게 삭제 여부를
물어라 — `log_csv/` 에는 실험 기록도 섞여 있어 임의 삭제는 금지다.

## 3. 확정된 사실 — 다시 재지 말 것

- **표본 단위 σ** 0.13/0.13/0.24 mbar (2026-08-20, 교체 전 개체), 교체 후는
  0.18/0.24/0.19 (10-20) · 0.31/0.37/0.34 (10-28, OSR 2048).
- **채널 간 무상관** r ≈ −0.005, 3채널 평균이 **정확히 √3** 로 감소 → 공통 요인 아님.
- **OSR 2048 에서 2.01배 악화** (ch0 2.08 / ch1 2.01 / ch2 1.95), 데이터시트 비율 ~2.0 과 일치
  → 칩 내부 오버샘플링이 지배. **OSR 8192 유지 결정됨** (2026-10-28).
- **19.3 Hz**, `TEMP_EVERY` 로 온도는 10 사이클마다, `CONV_TICKS=3`.
- **ch2 는 원래 잡음 최대 개체**이고 2026-08-26 거치 후 **+3.7 mbar 오프셋 계단**을 낸 이력이
  있다 (패키지 응력, 액체 배제됨 — §10.4). 재영점이 흡수해 무해하나 **감시 항목**이다.
- **1초 평균 공통성분 자기상관 1/e 지연 82초** (10-20).

## 4. 기각된 가설 — 다시 시도하지 말 것

| 가설 | 기각 근거 |
|---|---|
| 실제 기압 변동 | 표본 단위 채널 간 무상관. 실제 기압이면 공통 모드여야 한다 |
| 전원 리플 / EMI | 같은 이유 (공통 모드여야 한다) |
| OSR 이 1초 평균을 결정한다 | OSR 2048 에서 표본 σ 는 2배 나빠졌는데 1초 SD 는 **오히려 낮았다** |
| 샘플 속도를 올리면 개선된다 | 평균 후 이득 없음 (10-28 측정으로 기각) |
| 튜브 속 액체 (ch2 계단) | 자세를 바꿔도 안 움직였다 (§10.4) |
| 30BA/02BA 보상 혼용 | 그건 **정확히 20배** 틀리는 별건이고 현재 정상(300~1200 경고 미발생) |
| 각속도 제어 수정(10-30)과의 연관 | `i2c_driver_node` 는 **구독이 하나도 없다.** 코드 경로상 무관 |
| **I2C 버스 오류 (비트 뒤집힘·먹스 오선택)** | **10-31 기각.** (a) σ 에는 못 끼어든다 — 디지털 오류는 가우시안 폭을 못 만들고, OSR 2048 에서 σ 가 정확히 2.01배 나빠진 것이 σ 의 출처를 칩 안으로 못박는다. (b) 스파이크에도 안 보인다 — 비트 오류의 지문은 **한 채널만·다음 표본에 완전 복귀·양자화된 크기**(D1 의 bit12/13/14 ≈ 1.6/3.3/6.6 mbar)인데, 벤치 15분 정지 기록(10-30, 3ch × 17,371 = **52,000회 읽기**)에서 NaN 0, 10σ 초과 0, >5σ 횟수 8/6/13 = 가우시안 꼬리 기대치(~7)와 일치. 주행 로그(10-26, 압력 갱신 40,434표본)의 한-채널 스파이크 13건은 **전부 수심 0.01~0.26 m, 전부 State=0(손으로 넣고 빼는 중)** — 30 cm 떨어진 포트 하나에만 닿는 물보라·수면 사건의 분포이지 버스 오류의 분포(시간·수심에 무관)가 아니다. (c) 저널 7일·7회 기동: 먹스 선택 실패 0, 읽기 실패 0, ADC 오류 0; 커널 I2C 오류 0. **상한**: 벤치 0/52,000 → 95 % 상한 ≈ 6×10⁻⁵/읽기. ※ 구조적 주의 — MS5837 의 ADC 읽기에는 **CRC 가 없다**(PROM 만 있다). 그래서 버스 오류는 이 통계 검사로만 잡히고, 300~1200 mbar 게이트는 bit17 이상의 뒤집힘만 거른다. 그리고 버스는 100 kHz 로 **보수적인 쪽**이다 — 400 kHz 로 올리면 오류 위험은 줄지 않고 늘 수 있다(긴 배선·먹스 경유). 규명이 끝나기 전에는 올리지 말 것. |

## 5. 작업 순서

### 단계 0 — 현 상태를 기록하라 (측정 전 필수)

```bash
systemctl is-active fish-robot
systemctl show fish-robot -p ActiveEnterTimestamp --value      # 경과 시간 = 워밍업 상태
ls -l /proc/*/exe 2>/dev/null | grep -c 'fish_robot_pkg/lib'   # 8 이어야 한다
i2cget -y 1 0x68 0x75                                          # 0x71 (J4 확인)
ros2 topic hz /sensor/pressure_raw                             # ~19.3 Hz
```

세 채널 온도를 적어라. **이것이 그 측정의 워밍업 상태다.**

### 단계 1 — 더운 상태 기록 (지금 바로 가능)

서비스가 이미 오래 돌고 있으면 센서는 더워져 있다. §13 의 예측은:

> 더운 상태에서는 공통성분이 작고, 1초 σ 가 백색잡음 기대의 **1.0~1.3배**에 머문다.

```bash
python3 src/fish_robot_pkg/scripts/press_char.py 900     # 15분
```

**분석 전에 예측을 글로 적어라.** 적은 뒤에 분석하라. 순서가 바뀌면 검증이 아니다.

### 단계 2 — 찬 상태 기록 (운용자에게 sudo 요청 필요)

§13 의 반대쪽 예측:

> 찬 상태에서 시작하면 온도가 수 °C 오르고, 1초 평균 채널 간 상관이 **+0.6 이상**으로
> 올라가며, 1초 σ 가 백색 기대의 **1.6배 이상**으로 나빠진다.

절차: 운용자에게 **서비스 정지 → 30분 이상 대기(식힘) → 재시작 직후 기록 시작**을 요청한다.
식히는 시간이 충분하지 않으면 이 단계는 **하지 말고** 그렇게 보고하라 — 어설프게 식힌
기록은 어느 쪽 예측도 검증하지 못한다.

### 단계 3 — 채널별 온도 민감도 계수

단계 1·2 자료를 합쳐 채널마다 `dP/dT` [mbar/°C] 를 회귀로 구한다.
온도 변화폭이 큰 단계 2 자료가 주력이다. 계수가 채널마다 얼마나 다른지가 **차압 자세
오차의 크기를 결정**한다.

차압 자세 환산: 30 cm 간격에서 **1° = 0.51 mbar** (`CLAUDE.md` §7).
두 채널의 `dP/dT` 차이 × 실제 온도차 = 가짜 기울기 [mbar] → 도로 환산해 보고하라.

### 단계 4 — 기존 자료와 대조

새 기록을 10-20 / 10-28 과 비교한다. **온도 변화폭이 비슷한 것끼리만** 1초 SD 를 비교하라
(함정 2). 표본 σ 는 온도와 무관하므로 그냥 비교해도 된다.

### 단계 5 — 막히면 멈춰라

식힐 시간이 없거나 운용자가 재시작을 못 해 주면 **단계 2 를 건너뛰고** 단계 1·3·4 만
보고하라. 단계 1 만으로도 "더운 상태에서 1.0~1.3배" 라는 예측의 절반은 검증된다.
없는 자료로 결론을 쓰지 말 것.

## 6. 검증 — 원인을 찾았다고 생각하면 반드시

검증은 "맞는 증거 찾기" 가 아니라 **반증 실험**이다. 아래를 **모두** 통과해야 한다.

1. **사전 예측** — 분석 전에 글로 적은 예측과 결과가 맞는가. 사후 설명은 증거가 아니다.
2. **양방향** — 더운 상태(약한 저주파)와 찬 상태(강한 저주파) 둘 다 예측대로인가.
   한쪽만 맞으면 "온도가 원인" 이 아니라 "온도와 상관있음" 일 뿐이다.
3. **정량 일치** — 온도 민감도 계수로 계산한 저주파 크기가 **실측 저주파 크기와 맞는가.**
   부호와 상관만 맞고 크기가 10배 틀리면 다른 원인이 더 있다는 뜻이다.
4. **모순 검사** — 결론이 §3 의 확정 사실(특히 **표본 단위 무상관**과 **OSR 2.01배**)과
   상충하지 않는가. 저주파를 설명하려다 표본 단위 결론을 깨면 둘 중 하나가 틀린 것이다.

## 7. 조사와 무관하게 확정된 것 — 건드리지 말 것

- **OSR 8192 유지.** 낮추는 안은 2026-10-28 에 기각됐다.
- **`/sensor/pressure_raw` 는 영구 생값.** IIR 복원 금지 (2026-08-26 결정).
- **죽은 채널은 NaN, 0.0 아님.** `std::isnan()` 으로 검사. `x == NAN` 은 항상 false.
- **보상 상수는 02BA 용.** 30BA math 를 쓰면 정확히 20배 틀린다.
- `PRESS_HZ` — 드라이버 레이트를 바꾸면 `hydro_estimator_node` 의 상수도 함께 바꿔야 한다.
